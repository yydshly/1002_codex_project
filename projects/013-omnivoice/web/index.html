多语言语音生成 / 技术理解

OmniVoice从文字，到声音。

把文字合成为语音，
克隆参考声音，或用属性设计声音。

它的本质是条件语音合成模型（TTS）。训练让模型学会“文字与声音的关系”；使用时，预训练权重根据文字和声音条件，生成新的声音编码，再解码成可播放音频。

理解重点

多语言是覆盖价值；参考声音条件 + 非自回归语音生成是核心能力。模型可以运行在个人电脑、企业服务器或云 GPU 上，部署位置与生成原理是两件事。

02

同一个模型，三种声音来源

目标文字决定内容；参考声音或属性决定声音条件。

ZERO-SHOT VOICE CLONING

让新文稿，用参考声音来说

输入短参考音频，模型利用其中的声音特征合成另一段文字。正常使用不需要为这个人重新训练模型。

必须输入
目标文字 text + 参考音频 ref_audio
可选输入
参考转写 ref_text；省略时调用 Whisper 转写
适用提示
参考音频建议 3–10 秒。可跨语言克隆，但参考语言可能影响口音。
Python · 用法示意
audio = model.generate(
    text="你好，欢迎来到今天的课程。",
    ref_audio="ref.wav",
    ref_text="这是参考录音里说的内容。",
)
三种模式均返回语音；这里展示接口，不在网页运行模型。

目标文字可以属于不同语言；参考声音也可来自另一种语言。语言数量表示覆盖，实际发音和稳定性需按语言验收。

03

声音编码、模型参数、参考提示

理解“把声音参数化”，需要分清这三个层次。

01 / 数据

声学 token

音频编码器把波形压缩为离散编号。它们表示这段声音的信息，类似一种模型可处理的“声音编码”。

37 · 215 · 82 · 601
编号为示意；不是逐个对应音高、性别等人工参数。
02 / 知识

模型权重

训练调整神经网络的大量数值，使模型学会文字、声音条件与声学编码之间的统计关系。

大量训练数据 → 学习 → 固定权重
这是模型长期学到的能力；普通生成时不更新权重。
03 / 条件

参考声音提示

使用时把参考音频编码，并与转写文字一起作为上下文，引导目标声音。可以缓存提示，重复使用。

参考音频 → 编码 → VoiceClonePrompt
保存的声音提示不是为某个人训练出的专属模型。
更准确的理解

先把声音编码为模型可处理的数据；训练让模型学会条件生成；克隆时用参考声音引导已有模型，生成新文稿的声音。

依据：音频编码器说明 · 训练数据处理 · 声音提示复用

04

一次语音生成，经历哪些步骤？

从可读文字，到离散编码，再到可以听到的波形。

  1. 1

    准备内容与声音条件

    输入目标文字。克隆模式准备参考音频和转写；设计模式准备声音属性；自动模式只需目标文字。

    输入
  2. 2

    文本编码 + 参考音频编码

    文本转换为 token。参考音频经 Higgs Audio Tokenizer 转成 8 组码本的声学 token，组成模型上下文。

    表征
  3. 3

    估计时长，创建待生成区域

    根据文字与参考转写等规则估计帧数，或指定 duration。目标区域初始全部为 MASK，表示未知编码。

    初始化
  4. 4

    双向 Transformer 多轮补全

    每轮利用文字、声音条件和已填的编码，并行预测空位；按置信度和码本优先级填入一部分，再进入下一轮。

    核心生成
  5. 5

    声学 token 解码为波形

    补全后的多组离散编码经音频解码器还原成波形；需要时进行音量处理、尾部修整及长文分段结果的拼接与衔接。

    解码
  6. 6

    返回数组，保存或播放

    返回 24 kHz 单声道音频数组列表。调用方可以保存 WAV、接入播放器，或加入自己的应用工作流。

    产出

依据：生成、提示与音频解码实现 · 规则时长估计

05

“双向 Transformer”到底是什么？

双向描述的是注意力的可见范围：当前预测可以参考前面，也可以参考后面。

预测一个空位，模型能参考哪里？

点击一个 MASK 格子，再切换注意力范围。

教学示意
已知条件：整段目标文字 + 参考声音提示
可参考的已填编码当前预测位置仍然未知的 MASK

Transformer 做什么

注意力机制让模型判断上下文中哪些信息有助于当前预测。多层网络融合这些信息，再预测每个时间位置、每组码本可能的编码编号。

双向带来的价值

已知整段文字，而且部分较后位置的编码也可能已填好。模型能结合两边的信息补空位，支持整段并行预测和反复完善上下文。

后面还没生成的真实声音仍然未知。模型看到的是当前位置上的编码或 MASK，不会提前得到正确答案。“双向”也不等于两个模型同时说话。

依据：论文模型结构与双向注意力 · 音频嵌入与输出头实现

06

离散掩码生成：多轮做“声音完形填空”

从全部未知开始，每轮预测许多位置，再填入一批编码。

8 组码本 × 12 个时间位置

每列对应同一时刻的 8 个声音编码，不是 8 个说话人。

教学示意 · 压缩为 4 轮
此前已填本轮新增· 表示未知 MASK
0 / 96 个编码已填
演示使用人工示例编号，不运行模型。真实默认生成 32 步，可选 16 步；实际每轮填入数量由调度、置信度和码本优先级决定。

为什么叫“离散扩散”

这里处理离散编号，用 MASK 表示破坏后的未知状态；模型学习恢复编码。推理逐轮减少 MASK，属于扩散语言模型风格的离散生成。

为什么可以并行

一次前向计算会预测多个空位，而非严格从左到右逐个生成。总速度仍受步数、序列长度、硬件和批量影响；并行不代表瞬间完成。

依据：论文采样方法 · 推理补全循环

07

技术栈，以及训练如何获得这种能力

音频表征、生成网络和推理调度共同构成核心。

AUDIO TOKENIZER

把连续波形，变成离散编号

Higgs Audio Tokenizer 融合 DAC 声学特征与 HuBERT 语义特征，通过 RVQ（残差向量量化）得到多组码本。后续层继续编码前面近似后剩余的误差，多组共同还原声音。

8组码本
1024每组有效编号
25帧 / 秒

例如 10 秒音频约有 250 个时间位置 × 8 组 = 2,000 个编码。每个位置的 8 组嵌入相加成一个输入向量；模型对 8 组分别预测。每组另有一个 MASK 编号。

依据：Higgs Audio V2 文档 · 编码器技术说明 · 多码本嵌入与预测

阶段 A · 训练

学习“给定条件，恢复声音编码”

  1. 准备带转写和语言等信息的音频数据。
  2. 编码音频，保留参考前缀，随机遮住目标编码。
  3. 网络依据文字与可见编码预测被遮住的部分。
  4. 对被遮住位置计算交叉熵损失，更新权重。

训练过程中也会丢弃部分条件，使模型具备无条件预测能力，供推理时 CFG 使用。

训练样本与损失掩码 ↗
阶段 B · 使用

固定权重，根据新条件生成声音

  1. 加载已训练的 OmniVoice 权重与编码器。
  2. 输入新文稿和参考声音 / 声音属性。
  3. 初始化 MASK，逐轮补全所有目标编码。
  4. 解码得到音频，并返回调用方。

零样本克隆通常直接进行这一阶段。想调整模型能力时，才另行考虑全量微调或 LoRA。

训练与微调指南 ↗
模型骨干Qwen3 初始化 + 双向注意力 + 音频输入输出层

从 Qwen3-0.6B 权重初始化，增加声学 token 嵌入与预测输出，按语音任务训练为 OmniVoice。推理加载的是 OmniVoice 权重；Qwen 提供训练起点，不能直接替换成任意聊天模型。

论文训练配置 ↗ · 模型构建代码 ↗
多语言数据大规模语音训练 + 清洗 + 语言采样平衡

论文报告约 58.1 万小时、来自 50 个开放数据集。通过清洗与处理、转写筛选、语言采样调整等措施训练多语言能力。语言覆盖广，数据量和实际质量仍不均匀。

论文数据部分 ↗ · 数据准备指南 ↗
条件引导CFG 增强文字与声音条件的作用

Classifier-Free Guidance 对比有条件与去掉文字、风格和参考声音条件的预测，放大条件对结果的影响。它属于推理阶段的概率调节，需要训练时的条件丢弃支持。

条件与无条件预测实现 ↗ · 条件丢弃配置 ↗
补全调度置信度 + 码本优先级 + 多轮填入

当前实现按预测置信度，结合扰动和码本惩罚排序，决定本轮填哪些空位。较低层码本更优先；已填位置在这条推理路径中保留，不反复遮回。默认 32 步，16 步可加快推理，质量需实测。

参数含义 ↗ · 补全排序实现 ↗
时长与长文规则估计 + 切段 + 声音连续性处理

时长估计使用字符、语言权重及参考转写时长比例等规则；speed 调整帧数，duration 优先于 speed。长文可切段，复用声音提示或首段声音，并交叉淡化衔接。默认后处理可能修剪尾部，指定时长不代表最终文件绝对精确到该长度。

时长估计器 ↗ · 长文与后处理 ↗
工程加速PyTorch / Transformers / Accelerate / FlashInfer

PyTorch 与 Transformers 执行模型；训练可用 Accelerate、混合精度与序列打包。可选 FlashInfer 合并条件分支计算，使用融合算子与 CUDA Graphs。加速收益依赖 GPU、批量与软件组合，不能把论文速度直接当成本机速度。

08

部署在哪里，怎么使用？

“本地模型”说明权重在计算环境中运行；这个环境也可以位于云端。

01

个人电脑

下载权重，在自己的设备推理。适合验证、研究、少量生成和本地工具。

准备 Python、PyTorch、模型与硬件支持。
02

企业服务器

在统一机器加载模型，供内部批量任务或应用调用。可管理模型缓存和任务队列。

HTTP 接口、鉴权和并发管理需要自行开发。
03

云 GPU

把同样的权重与依赖放在云主机推理，再通过自己封装的服务远程使用。

云是部署位置，底层仍运行 OmniVoice 权重。

最小使用路径

1
准备计算环境

Python ≥ 3.10。按设备安装匹配的 PyTorch / torchaudio，再安装 OmniVoice。NVIDIA 使用 CUDA；Apple Silicon 使用 MPS；Intel Arc 使用 XPU。CPU 路径可回退，但速度需验证。

运行依赖 ↗ · 设备选择 ↗
2
安装库，选择入口

在新的虚拟环境中操作。PyTorch 的具体安装命令请按 官方安装选择器匹配设备与 CUDA。

安装与本机 Gradio 界面
pip install omnivoice
omnivoice-demo --ip 127.0.0.1 --port 8001

也可使用 omnivoice-infer 单项生成，或 omnivoice-infer-batch 批量 / 多 GPU 推理。Gradio 是官方示例入口；生产服务需另外封装。

3
加载权重，输入文字与参考声音

首次使用模型 ID 会下载预训练资源。之后可使用缓存，或把模型 ID 替换为准备好的本地模型目录。

Python · NVIDIA CUDA 示例
from omnivoice import OmniVoice
import soundfile as sf
import torch

model = OmniVoice.from_pretrained(
    "k2-fsa/OmniVoice",  # 也可传入本地模型目录
    device_map="cuda:0",
    dtype=torch.float16,
)
audio = model.generate(
    text="你好，欢迎来到今天的课程。",
    ref_audio="ref.wav",
    ref_text="这是参考录音里说的内容。",
    num_step=32,
)
sf.write("out.wav", audio[0], 24000)

Apple Silicon 将设备设为 mps，Intel Arc 设为 xpu，并匹配相应环境。缺省 ref_text 会加载额外的 Whisper ASR；手工提供转写可以跳过它。MPS 路径中的音频编解码器会转到 CPU 执行。

4
验收与接入应用

检查文稿读音、内容完整性、音色、停顿与输出时长，再测单条耗时、批量吞吐和硬件占用。接入应用时保存 / 播放数组，按需求增加 API、排队、错误处理和存储。

可以完全离线吗？

在提前准备全部模型资源和依赖后可以离线运行，包括 OmniVoice、音频编解码器，以及需要自动转写时的 Whisper。普通推理不必调用收费云模型 API。

代码与权重的授权不同

仓库代码为 Apache 2.0；官方模型权重标注 CC-BY-NC。实际采用时应分别阅读代码和权重条款，不能由代码开源推断权重允许商用。

适用场景，以及需要另外补上的能力

将“文字 → 声音”作为工作流中的一环。以下场景是基于公开能力的采用方向。

内容生产

多语言旁白与朗读

文稿、课程、讲解或资讯转语音，统一声音并批量制作。翻译与编辑文稿属于上游步骤。

交互应用

助手的语音输出

把语言模型生成的回答转成声音。识别用户语音、对话逻辑和播放中断需要其他组件。

角色与原型

声音设计与角色试音

用声音属性探索角色风格，或用已授权的参考声音试制旁白。需实际试听属性一致性。

研究与工具

语音模型实验与微调

学习离散声学编码、掩码训练和条件生成，评估特定语言 / 文本，再按需要调整模型。

从公开功能出发，判断能做到哪一步
容易产生的理解更准确的边界
音色克隆 = 每个人训练一套参数通常用参考提示引导已有模型，不重新训练该人的权重。
646 种语言 = 每种质量都一样覆盖广，语言资源与表现不均；声音设计尤其要单独验收。
跨语言克隆 = 自动翻译配音需要提供目标语言文稿；翻译、字幕对齐及剪辑需额外接入。
本地模型 = 只能在本机调用权重可在服务器或云 GPU 运行，再由应用通过接口调用。
Qwen 初始化 = 可接任意聊天模型实际使用经过语音训练的 OmniVoice，接口不是通用 LLM 适配器。
并行生成 / 长文分段 = 实时流式播放当前 generate() 生成后返回完整结果；实时流式交付需另外实现并验证。
