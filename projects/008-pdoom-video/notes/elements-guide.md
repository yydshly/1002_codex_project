# 角色与要素：准备和驱动

研究日期：2026-10-04。上游版本：`fa546a38092e75f2b079e6a86d6abc54dd525d17`。[实际页面](../web/elements.html) 展示原始源码重绘，新增的是目录、说明及驱动包装代码。

## 现成资产的复用范围

| 类别 | 本次展示 | 来源与准备要求 |
| --- | --- | --- |
| 共享角色 | Clawd、研究员 | `clawd.js`、`cast.js`，需要 `core.js` 和 p5 / p5.brush。研究员还使用 Clawd 的共用动作、表情与辅助函数 |
| 角色组合 | 群演 Clawd | 多次调用同一个角色函数，给每个人设置位置、配件、颜色与动作时间；不是另一套独立造型 |
| 章节客串 | Shoggoth、Sydney、Basilisk、Gato、Chinchilla | 分别导出为 `CAST` 函数，仍依赖章节私有辅助函数；需要保留对应章节环境，或连同依赖一起提取 |
| 共享场景与道具 | 舞台幕布、表盘、打气筒、聚光灯、放射背景 | `props.js` 中已有绘图函数。幕布需要前后景顺序；把手、液柱等用数值控制，角色接触关系仍要编排 |
| 绘图基础 | 矩形、椭圆、星形、心形 | `core.js` 提供点列表与 `paint()`；`heartPts()` 在 `clawd.js`。新按钮、灯泡或其他道具需要组合这些形状或新增绘图函数 |

原作章节还有与固定剧情绑定的场景和道具。这里集中展示共享组件与已导出的客串，不把章节里的每个图形都视为可独立调用的现成组件。

## 准备给编码模型的交付物

1. **造型函数**：角色源文件、默认静帧、依赖和坐标说明。Clawd 的 `(x, y)` 是脚底中点，`u` 是尺寸单位；研究员的 `s` 是独立尺寸单位。
2. **表演接口**：参数名、单位、允许值、挂点和示例。`aL / aR` 使用弧度，0 为侧向伸手，正值抬手。`dy / sq / rot` 描述身体升降、伸缩和旋转。
3. **场景与道具**：绘制顺序、布局、可动部件和接触点。Clawd 持物钩子为 `armL / armR`，研究员为 `handL / handR`；挂点提供位置，道具本身仍需要绘图代码。
4. **创作约定**：调色板、画笔、纸纹、节奏、运行样例、目标故事、分镜格式和输出规格。已有参考是 `upstream/ANIMATION_GUIDE.md`、`upstream/STORYBOARD.md` 与六秒实际场景。

先检查静帧、表情、极端姿态、持物与遮挡，再让模型编排新故事；检查动作关键时点后连续出片。

## 怎么驱动

模型在创作阶段读取接口、写分镜和场景代码。运行阶段计算每个时刻的参数，再调用绘图函数。`move(style, t, seed)` 返回动作预设的身体和肢体变化；走到画面另一侧仍需用 `kf()` 等工具另算 `x(t)`。预设节奏来自原作的 88 BPM 与 0.21 秒偏移，换音乐要调整时间约定。

网页控制台直接改变参数，运行原始 `move()` 与角色函数，再由原始 `renderAt(t)` 完成绘画合成。右臂滑块覆盖动作预设的右臂角度；其他姿态按预设时间计算。控制台显示同一套实际调用代码，修改角色轮廓则需修改造型函数。

研究员的旋转参数为 `spin` 相位，Clawd 使用 `sx` 横向缩放。新增包装用 `acos(sx) / (2π)` 转换，使两种原始绘图函数采用相同的横向伸缩；跑步另把预设的步态相位传给研究员的 `run`。这些是接口适配，原始角色源码没有改动。

控制台只取两种共享角色与部分表情、配件作为演示；完整参数仍以原始源码为准。它不是给模型的在线请求接口。页面的创作任务生成器附上当前角色、参数、文件位置和交付要求，供能读取当前项目的编码模型继续写新场景。
