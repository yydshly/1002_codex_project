# 从粗模到可运行项目：当前页的下一段验证

2026-10-07。目标保持不变：用户的图或粗模持续决定空间，模型完善同一个场景，出口是可继续编辑和运行的 3D 项目。

## 本次接通的链路

“生成精细场景与项目”先采集语义布局与粗模视角，真实控制模型返回整场景外观方案。第二个模型任务据此编写部件几何数据，包括门窗、屋顶、灯室、栏杆、树干、叶片和船体。执行器用这些数据构建新网格，绑定回原对象，再导出静态 GLB，并由独立 GLTFLoader 重新解析检查。最终 ZIP 同时包含动态网页回放、原布局、模型几何、实际输入和任务记录、全部本地渲染依赖、纹理、HDR、扫描资源与许可。

用户提交一次，内部可以调用模型多次。发现已知部件变换问题时，页面采集当前灯塔、树冠和建筑近景，连同原布局交给模型自动修正一轮。也能点击“依据画面继续完善”，选择单个对象、同类对象或整个场景；每次保留上一候选供还原比较。自动循环目前只覆盖明确的变换缺陷，不是完整视觉评估器。

## 局部几何怎样控制与保存

单个和同类模式仅覆盖未锁定的小屋、灯塔、棕榈和船。同类模式按原 plan 选中该种类全部未锁定对象；整场景模式重新生成全部四类未锁定对象，仍保留原区域、物体 ID、锚点、包络与已确定的方案朝向。精细候选中的“只精修选中对象”始终只请求当前物体。

局部任务将原布局、当前完整几何、指定 `scopeIds`、选中近景与另一侧交给模型。模型在后端返回 `tidewater-fine-geometry-patch.v1`，只包含这些对象的完整替换模板和实例，以及必要的新材质；借用已有材质时不重复声明。后端校验范围和朝向，再把补丁合并成完整 `tidewater-fine-geometry.v1` bundle。共享模板或材质如果被局部修改，会为新版本分配独立 ID，范围外仍引用原定义；只由被修改对象使用且已经过时的依赖可以移除。

页面在应用前独立比较前后完整 bundle 的范围外依赖：每个 instance、所用 template 的部件与变换、所引用 material 的值和原朝向必须严格相同。恢复／导入以及项目打包再次比较；自包含网页项目启动时也用随项目保留的上一版重新验证。检查根据实际数据完成，不相信模型回执中的“已经保留”声明。源指纹必须对应同一份原 plan，锁定对象不会进入局部范围。任何校验、模型调用或合并失败都保留上一候选；打包失败时保留已经应用并保存的新几何，可重试交付。相关实现见 [补丁契约与合并](../web/fine-geometry-core.js)、[客户端范围保护](../web/fine-refinement-core.js)、[当前页请求与恢复](../web/scene-completion.js) 和 [项目交付](../web/scene-delivery.js)。

## 我们怎样控制模型

- 用户空间：原区域轮廓、稳定 ID、锚点、包络与锁定来自 plan。模型不能新增实例或移动原对象。朝向保持本轮外观方案；锁定对象没有细化实例。
- 模型决定：部件形状、顶点／曲线、部件组合、材料参数、模板复用。它实际设计新的形体，不只是选择已有外观预设。
- 执行器决定：先完整校验引用、数值、预算和几何，再整批等比归位与接地。任何一项失败，拒绝应用；原草案与上一结果保留。
- 过程可查：源指纹、真实任务 ID、图片哈希、模型输出哈希、原始输出和校验记录保留。模型版本不在回执中返回时，不虚构具体名称。
- 产品出口：静态可编辑 GLB 与可独立运行的网页工程；前者记录动态水面、地形混合与天空的兼容近似，后者保留原运行代码。

这个原型使用本机已登录的 Codex CLI / ChatGPT，不是 Opus 服务。部件数据由控制模型编写，网格由执行器构建；这条新增链路没有调用神经图片到 3D 模型，也没有让模型预测新的照片纹理。材质图、HDR 与扫描资源沿用已有登记资源。

新增 `ribbon` 仅扩展通用网格基元：模型明确提供连续的左右边界对 `[L0,R0,L1,R1,…]`，执行器按相邻边界生成薄带三角形，UV 沿中心线弧长分布，沿用双面 PBR 材质。它没有厚度，也不自动推断曲线、插入站点或补出树冠预设；曲率、下垂、宽度和分布仍由模型坐标决定。原有 `curved-tube` 语义保持。薄带更适合表达弯曲小叶，但不能据此宣称接入了神经纹理生成或达到照片级效果。

## 本次验证暴露出的真实问题

第一份真实几何任务 `964354b1-7d8b-4df5-b69a-cbce19c01ee8` 覆盖原布局的 17 个物体，生成 4 个模板和 249 个展开部件。ID、锚点、旋转后的包络、接地与有限网格检查通过，但灯塔立柱原位重叠、圆环尺寸轴错误，棕榈叶片也需要审查。原始输出完整保留，未通过偷偷改变 primitive 语义修饰结果。

从当前页一次提交的后续任务 `69400170-d405-441f-adad-2bf894d477e5` → `09763a9c-7cab-4c4b-8364-fd0170fb4221` 已完成模型方案、新网格、装配和交付检查：原布局 25 个 ID 全保留，17 个物体有新部件；导出的 1,047,619 个三角形和 7,697 个网格，在独立重新解析后保持。仍发现灯塔圆环的局部轴错误，因此继续将实际近景交给模型任务 `d6fe26bb-14f5-477c-9257-52846275ad90` 修正。记录见 [首次完整流程存档](../assets/fine-scene-first-full-flow.export.json) 与 [首次模型几何检查](../checks/fine-geometry-model-results.json)。

这说明“粗模 → 模型生成细节 → 检查 → 可运行项目”可以跑通，也说明合法网格不等于可信写实效果。不能以文件大小、三角形数量或成功状态替代近景品质验收。

## 扩展前的 v3 交付与独立回放

局部精修扩展前的最后一轮任务 `12274295-1a57-4e24-b850-94d4afd1e997` 实际读取原布局与三张当前近景，依据棕榈细化要求重新生成 17 个物体、704 个部件。保留此前几何、真实任务回执和每轮输入；该结果作为历史候选冻结在 [v3 独立项目](../web/versions/2026-10-07-fine-components-v3/index.html)，完整数据见 [v3 场景存档](../assets/fine-scene-final.export.json)。

当前页新增本机持久交付，打包失败前也先保存已完成的候选。自动修正失败保留首轮有效几何；恢复待检查版本失败时回到此前确认版本。确认旧版时同步更新活动候选，避免刷新后又显示已放弃版本。原先确认的模型场景未被本次实验覆盖。

GLB 通过独立重新载入，保留 25 个源 ID 和 1,051,879 个三角形。精确字节复用保留节点、变换、材质和图像引用，将 GLB 从约 98.9 MiB 减至 42.4 MiB；自包含网页项目为 66.0 MiB。服务对上传文件进行尺寸、文件头及 SHA-256 校验，再原子保存到 `web/assets/fine-deliveries/97fa3c1f-4b78-4a4e-95c0-6e42f5c3c2e9/`。

已用独立 ZIP 读取器核对 CRC 与 70 个清单文件的 SHA-256，再从解压目录启动项目。浏览器显示“项目就绪 · 17 个精细对象”，完整布局／海岸视角、粗模对照、白天和日落入口可用，未出现浏览器错误；项目不访问控制模型服务。记录见 [文件验证](../checks/fine-scene-delivery-disk-results.json)、[浏览器验证](../checks/fine-scene-browser-results.json)、[当前页截图](../assets/fine-scene-current-page-v3.png) 和 [独立项目截图](../assets/fine-scene-portable-v3.png)。

视觉结论仍是**可运行的受控精细化原型**：棕榈主叶轴过粗，叶片仍显机械；建筑与船只等细部也没有达到照片级品质。此次验证不能证明任意参考图可直接还原 3D，更不能证明任意粗模一次生成便能写实达标。

## 新局部任务的实际结果

## 跨场景基准与双岛实际运行

已建立三个手绘输入：窄岸小屋与灯塔、双岛航道与锁定灯塔、少树小港与双屋。它们分别覆盖横向窄岸、纵向双岛、凹形小港，不同物体数量，以及有锁定灯塔／没有灯塔的组合。工具和静态校验清单见 [build-fine-benchmarks.mjs](../tools/build-fine-benchmarks.mjs) 与 [manifest.json](../assets/fine-benchmarks/manifest.json)。

三份基准的计划格式、物体包络、道路支撑、原水位和受保护锚点静态检查通过；没有生成新的参考图。双岛已经实际运行：方案任务 `f33ff052-5c90-4d3a-837c-6998c835da69` → 细几何任务 `a9f7a65f-71b0-43b1-8215-1aa6dc15411d`，来源指纹为 `plan-v1-1be8df920e46eab6-1943`。6 个未锁定物体生成 97 个部件，原 12 个来源 ID 在导出中保留，锁定灯塔 `dual-fixed-lighthouse` 不进入模型细化。

交付 `452dea3d-3ee7-48f9-a341-537dcd550572` 已落盘并独立验证 ZIP CRC、63 个清单文件的 SHA-256、6 张实际输入和 GLB 顶点／索引。GLB 20.2 MiB，网页工程 39.3 MiB；解压后浏览器实际显示 6 个精细对象，无浏览器错误。见 [双岛场景存档](../assets/fine-benchmarks/dual-island-lock.export.json)、[文件核验](../checks/fine-benchmark-dual-island-delivery-results.json)、[浏览器记录](../checks/fine-scoped-browser-results.json) 与 [双岛独立回放截图](../assets/fine-benchmark-dual-island-portable.png)。锁定灯塔保留原粗模外观，其他生成物也较简化；此结果验证不同布局的输入、绑定、锁定和交付链路，仍未通过写实品质验收。其余两份基准尚未调用模型，目前没有全部基准的首次成功率或修正通过率。

局部精修真实任务也经过独立原始补丁重放、事件／图片哈希与范围外依赖比对，见 [真实生成核验](../checks/fine-scoped-generation-results.json) 和 [精修工程核验](../checks/fine-scoped-delivery-disk-results.json)。本轮 129 项功能单测、两项交付工具测试及既有 95 项核心检查通过，共 226 项；实际当前页刷新、独立工程粗模往返和多视角检查另行记录。

## 接下来如何达到产品目标

先针对海岸展示／漫游场景定义可判断的目标：建筑细部可信、植物不呈纸片轮廓、船体和内舱连续、部件接触合理、多个视角一致、目标设备运行流畅。逐场景记录首次成功率、修正后的通过率、耗时与输出体积，再决定是否可提供“一次提交直接使用”的承诺。

模型生成的部件语言适合可控组装，但能力边界明确。单个与同类对象的完整局部几何替换、共享依赖隔离和范围外重新验证已经实现；更复杂的写实形体仍可接入专用网格模型、资产检索或用户提供的精细参考，并进入同一套对象绑定、归位、版本和验收流程。自动碰撞／拓扑检查、自动视觉评分和跨场景稳定交付仍未完成，不能承诺任意粗模一次生成即可达到目标品质。
