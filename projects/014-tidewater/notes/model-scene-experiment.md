# 粗模之后：本轮模型编写的真实 3D 候选

用户希望借助模型，把已经画出的粗模推进为更合适的 3D 效果。2026-10-05 的尝试保留原创作页，并增加独立的 [模型方案比较页](../web/model-scene.html)。

## 这次模型做了什么

当前 Codex 编码模型依据已有页面中的布局与对象信息，编写了一套海岸场景的几何和材质代码，以及明确的候选配方。输入布局包含三块陆地、三个水域、一条道路、一座小屋、一座灯塔、八棵棕榈和七艘船；主陆地已有本地细化。候选采用暖白灰泥、陶瓦、木构、青绿水面与浅沙，补充建筑、植被和船只细部。渲染代码复用固定版本 Tidewater 原生 Engine；原粗模渲染和运行时源文件保留。

这次没有在线模型 API、模型密钥、图像识别或专门的 3D 生成服务。这里的“模型方案”指本次编码模型实际写出的场景代码。网页的“预览本轮方案”按钮运行已经生成的代码和配方，不能把任意新文字直接转换成另一套场景。程序着色与风格化几何也不等于照片级建模或参考图重建。

## 如何保持控制

比较页只读原 IndexedDB 草案，用相同的实体 ID、归一化坐标、高度和轮廓分别显示粗模与候选。锁定实体使用原粗模几何；原水域仍采用相同的水位与支撑规则。更细致的几何依附原实体 ID，继续支持选择和镜头观察。整体光照可以改变视觉表现，锁定不代表冻结光照、视角或像素。

候选是独立协议，记录方向、生成来源、配方与说明，不把未知代码或任意字段塞进原 plan。保存记录与完整源计划指纹关联，存入独立数据库；原布局不会被覆盖。导出的 GLB 包含实际几何、法线、顶点色与对象分组，不含浏览器动态水面着色或生成代码。导出的候选 JSON 与上下文用于后续重新生成和恢复。

## 这个尝试验证什么

本轮验证“模型编写细化代码 → 原布局上的真实 3D → 与粗模比较 → 独立保存与 GLB 交付”。下一阶段若接入模型服务，应把结构化上下文、外观目标和参考信息交给模型，获取新候选或资产，再执行同样的校验、比较与接受流程。服务接入需要明确供应商、模型、调用方式与可用凭据；本轮没有冒充这部分能力。

通用产品仍需要资产引用、模型输出验证、版本迁移、局部目标选择、几何边界与性能约束，以及在线生成任务的错误、取消和恢复。当前只支持本轮海岸资产套件，不能覆盖任意风格或场景。
