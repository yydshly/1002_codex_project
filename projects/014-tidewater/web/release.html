库的价值，与我们扩展的价值

源库

实时世界的技术底座

Tidewater 提供海岛、FFT 海浪、天空云层、植被、角色与钓鱼体验；自研 WebGPU / WGSL 引擎每帧更新和绘制。模型可以编写这些代码，画面由程序与素材共同产生。源库本身没有图片生成接口，也不是通用场景生成 SDK。

控制产品

让空间意图持续有效

你的图或粗模确定轮廓、位置、尺寸、对象 ID 和锁定。模型读取布局、实际视角与参考，提出外观配方和几何；执行器校验后按原身份装回场景。指定局部修改时，还会核对范围外的几何、材质与朝向。

实际成果

让候选成为可交付项目

原布局、候选、参考、模型回执和历史一起保存；同一镜头比较不同版本，多角度检查，再决定采用。网页保留实时效果，GLB 提供静态网格，独立工程包含重放需要的资源。

核心链路：输入 → 生成 → 验证 → 修改 → 交付

输入：绘笔布局，或人工标注的参考图；已有粗模提供空间依据。图片表达外观，结构化 plan 表达对象与关系。

生成：控制模型组织方案与部件几何；专门的图像到 3D 模型提供神经网格；材质、扫描资源、光照和渲染器共同呈现效果。

验证与修改：检查来源指纹、稳定 ID、锁定、空间包络、资源引用与预算；对照粗模、近景和另一侧，局部修改另存版本。

交付：布局 / 提案 JSON、视角截图、可编辑 GLB、自包含网页工程与来源记录。动态水面和光照在网页运行；GLB 保存静态快照。

区别于只发一句话：模型每次都有明确的作品、范围与验收依据；产品保留已经确认的空间和历史，支持只改指定对象。

探索过程与已经验证的能力

  1. 先研究源库的实时渲染，接入对象、环境、镜头、锁定和撤销。
  2. 增加图片标注与语义绘笔入口，把空间想法转换成 plan 和真实 3D 粗模。
  3. 加入 PBR 材质、扫描素材与 HDRI；实际生成 TRELLIS.2 小屋和 TripoSR 棕榈、灯塔、船。厚重的神经棕榈树冠未采用为默认效果。
  4. 明确“沿用我的图或粗模”这一目标，接入真实控制模型与部件几何，完成同场景生成、局部精修和范围外保护。
  5. 保存原三岛 v5、几何历史、GLB 与独立工程；增加对象介绍、参考、固定视角和客户提案。六木屋 A/B 只作为独立业务验证。

原场景实际运行的控制适配器是 Codex CLI / ChatGPT，回执没有返回确切模型 ID，因此不标成 Opus。新精细几何来自模型定义的部件、曲线与薄带；没有为原三岛新增整场景神经纹理。GLB 重载、独立工程、来源一致性及局部保护均有检查记录，视觉品质仍需按用途验收。

文旅与营地方案

在原空间上补对象用途、路线、说明、素材参考和局部 A/B，用固定镜头与客户沟通。预订与真实项目数据在有业务需求时接入。

品牌与产品展示

保留空间结构，将指定对象替换为有来源的商品或品牌资产，再增加热点介绍、相机预设与展示导出。

教学、游戏与虚拟拍摄

把空间、对象与事件结合，按需求加入导览、任务、规则或镜头时间线。现有底座可复用，玩法和业务逻辑需要具体实现。

当前版本怎么用

网页可直接使用：原场景浏览、粗模对照、对象介绍、提案编辑、本浏览器保存、JSON 导入导出、参考上传，以及已有 GLB / 工程下载。原生工作台与粗模使用 WebGPU，精修场景使用 Three.js WebGL2。

新生成需本机服务：控制模型通过本机 4198 服务运行，TripoSR 通过本机 GPU 服务运行。远端静态站点不运行这些服务，也不携带账号凭据；下载源码后可以按 README 启动。

继续优化的方向：海岸水面过渡、植被自然度、建筑与船只近景、光照和目标设备性能。当前先保留效果，后续锁定原布局，指定局部优化、另存候选并在同一镜头验收。

当前主要覆盖海岸场景的七类区域 / 对象；图片入口仍由人标注，不能承诺任意输入一次生成就达到最终写实品质。未来可扩展已有资产、规则、事件、镜头和真实地图输入。
