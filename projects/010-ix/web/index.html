01 · 这个库的产品目标是什么？

让代码结构成为共享、持久、可追溯的索引，供人和 AI 按任务查询。人可以找到实现、探索依赖、打开源码；AI 可以获取目标相关结构和证据，减少反复读取无关文件。图是理解的载体，应衡量理解正确率、任务时间和上下文成本。

当前能力覆盖接手、定位、排查、评审和重构等辅助工作。进一步完成业务任务，需要业务语义、运行证据、可调用接口和结果验证。

Ix 定位依据
02 · 数据库怎样关联函数？深度在哪里？

Tree-sitter 和语言规则提取定义、调用、导入及容器，再用导入绑定和符号索引解析目标。确定性 ID 结合工作区、路径和限定名。图补丁把节点、边与来源交给 Scala memory-layer，在 ArangoDB 持久保存。解析器建立关联，数据库保存和查询。

节点：N1 submitOrder / N2 checkoutOrder / N3 calculateShipping
边：{ src: N1, predicate: CALLS, dst: N2 }
    { src: N2, predicate: CALLS, dst: N3 }
反向从 N3 查询：1 跳 → N2；2 跳 → N2、N1
示例：ix impact calculateShipping --depth 2

数据库保存直接关系，间接关联通过路径体现。深度表示距离查询起点多少跳，函数没有固定深度。当前 impact 默认 1、上限 3。调用、导入、包含、引用、继承 / 实现是不同关系，应明确方向和类型。

mtime 与 SHA-256 筛选变化，hash、提取器、来源与替换字段协调更新和删除。普通 map 默认 topology-only，过滤 chunk / claim；正文可从本地源码读取。图谱 revision 与 Git commit 不同。

图补丁 · 查询深度 · 建图模式
03 · 能力是否只看修改差异？

能力包括定位与阅读、关系导航、结构解释与影响范围、清单和架构检查、图谱持久维护、按目标组织 AI 上下文。history / diff 是其中一组；context --from-issue 可从问题描述组织上下文。

也有跨工作区包导入 stitching，以及 GitHub issue / PR / commit 等资料摄取。不能据此认为已恢复全部微服务 HTTP、消息或数据库关系。conflicts 检查图中 claim 的矛盾，不能当作通用代码故障检查器。

explain 普通流程为事实收集、规则推断、模板呈现；MCP 复用 CLI。AI 宿主负责模型判断与后续执行。

04 · 展示是结构图，还是图到代码？

现有输出包括文字摘要、位置、关系、路径、影响候选、JSON 与紧凑 LLM 记录。官方 view 通过本地代理接入 Compass，浏览同一后端图谱及系统 / 子系统结构。本次未运行 Compass，未核验具体图库、布局和界面。

我们的展示设计让系统概览、局部关系图、解释与源码证据联动。从“这个功能如何实现”出发，得到模块、实现说明、代码位置和待确认项，回到源码核对。价值按能否正确完成任务判断。

05 · 能定位 Bug、分析性能吗？

Bug 排查可从报错符号或问题描述定位实现，查调用入口和依赖，再阅读源码与测试。确认根因需要复现、输入、堆栈、日志及测试。

smells / subsystems 和按 dependents 排序的 rank 可调查结构热点。连接多不等于 CPU 占用高，CALLS 边不表示实际调用次数，静态 trace 没有请求耗时。

例如订单接口慢，Ix 可定位结算函数及循环中的数据库访问；Profiler、真实 Trace 与 SQL 数据才能确认是否逐条查询、哪里慢、时间花在 CPU 还是等待。公开 CLI 未见内置性能采集，连接运行数据属于扩展方案。

静态 trace · 运行时 Trace · Profiler
06 · 构图通用吗？可扩展价值在哪里？

“解析 → 实体与关系 → 持久图 → 按目标查询”是通用思路，每种语言、框架和关系仍需适配提取、解析、来源与更新规则。代码属性图可进一步组织语法、控制流和数据流，不能据此认为 Ix 已有完整 CPG 分析。

四层扩展：扩大语言与框架覆盖；增加类型、控制流、数据流、业务规则和状态；把日志、Trace、Profiler、测试与部署版本关联回源码；绑定接口、契约、权限和执行能力。

高价值结果可以是被验证的故障候选、可执行迁移计划、可退役资源、可复用能力或完成的任务。CALLS 不能直接视为业务因果、行为模型或正确性证明。

这个函数是什么？

展示目标实体及直接相邻的调用关系。

ix explain verify_token

  • verify_tokenauth/token.ts · 验证令牌的示例函数

关系图是结构线索；实际业务逻辑仍需结合源码阅读。

看看这段示例源码如何对应关系图
// auth/routes.ts（本页教学代码）
function login(token) {
  const claims = verify_token(token);
  return load_user(claims.subject);
}

// auth/token.ts
function verify_token(token) {
  const key = load_public_key();
  return verifySignature(token, key);
}

解析器识别出 login → verify_token、login → load_user 和 verify_token → load_public_key。图中只展示示例项目内的函数；外部签名验证实现没有展开。刷新会话和测试函数提供另外两个调用入口。

运行要求 · 测量范围
它能自动“理解所有业务”吗？

它提供代码结构和证据。某个条件为什么存在、需求是否正确、实际运行会发生什么，仍需结合源码、业务资料和测试判断。

它与文本搜索、向量检索有什么关系？

文本搜索找匹配内容，向量检索找相似内容，结构查询沿明确的实体和关系寻找关联。Ix 提供图谱查询并保留文本搜索，语义搜索另有云服务条件；不同方法适合不同问题。
