# Solaris 鼠标交互能力分析

资料核查日期：2026-10-04（Asia/Shanghai）。本报告以公开资料为依据；本项目未获得 Solaris 访问条件，未实测模型。研究对象是用户给出的 [GKev1n 帖子](https://x.com/GKev1n/status/2106629610590888065)，技术依据为 [Runway 官方介绍](https://runway.com/news/research/introducing-solaris)与 [Solaris 论文 v1](https://arxiv.org/html/2609.00776v1)。

本轮已从帖子中的室内效果扩展到两份一手资料的全量公开示例，包含直接鼠标操作、未公开具体手势的界面效果、语言操作、关联响应和未来设想。逐项的手势、效果、原理分析、验证方法及来源见 [完整能力目录](capability-catalog.md)；真实场景的任务流程与演示质量标准见 [场景研究](scenario-design.md)。本地首页已改为官方视频与论文画面的证据展示，旧规则原型只作为归档对照，不作为模型展示。

## 最重要的判断

鼠标在这里可以同时提供**位置、持续动作和操作意图的线索**。值得分析的并非光标能够移动，而是“拖在哪里、当前想做什么、画面是什么”共同影响后续画面。因此，同一条拖动轨迹可能被解释成搬动物体、改变尺寸、转动视角或施加一种效果。

公开演示支持继续研究这种交互范式，但目前无法据此确认每个像素都能被精确控制、对象具有持久可编辑的三维结构，或生成结果符合真实物理规律。本项目的下一步应测量“操作与视觉响应之间的稳定关系”，不能把画面好看直接当成控制准确。

## 鼠标究竟控制了什么

以下用四个环节拆解用户体验。这是便于实验的解释框架，不是已公开的内部模块图。

### 1. 点击：指定作用位置，或切换效果来源

点击至少存在两种可能语义：

- **作用目标**：告诉系统希望改变哪片画面，例如选中灯或沙发。
- **操作上下文**：先点一个对象，再让后续动作使用它的颜色、纹理、风格或行为。此时点击类似选择工具。

这两种语义需要不同验证。前者要测对象边界、重叠处和小物体是否容易选中；后者要测工具状态能否保持、能否取消、是否误作用于其他目标。不能因为点击了一个对象就断定内部存在独立分割网络、对象 ID 或传统命中检测模块：可观察的选择效果与实现方式是两个问题。

### 2. 按下并拖动：提供空间路径和时间过程

一次拖动不仅有起点和终点，还有弯曲路径、速度、停顿、按钮保持与释放。对用户而言，这些信息决定“边拖边看、随时修正”是否成立。

若模型只忠实实现终点变化，可能仍适用于一次性编辑，却不足以提供顺手的连续操纵。相反，画面在拖动途中发生变化，也不自动证明完整轨迹被细粒度使用：效果可能主要跟随最近坐标、累积位移或较低频的动作摘要。这是需要实测区分的地方。

设计检验时，应使用“相同终点、不同路径”与“相同路径、不同速度”两组对照，而不是只看一次拖动成功的录屏。

### 3. 语义上下文：决定这条路径是什么意思

可把交互理解为一个概念关系：

`视觉响应 ≈ 当前画面 + 已发生动作 + 当前任务/效果语义 + 会话历史`

它只描述应该考察的因素，并非模型的实际公式。对于同一张画面、同一条右拖路径，可以分别设定以下实验条件：

| 事先明确的操作意图 | 希望观察到的响应 | 检验目的 |
| --- | --- | --- |
| 移动这盏灯 | 灯的位置改变 | 空间位移是否可控 |
| 放大这幅挂画 | 尺寸改变，中心或锚点有稳定规则 | 变换语义是否稳定 |
| 改变观察角度 | 整个场景的视角改变 | 目标对象与相机操作能否区分 |
| 把当前材质刷到目标上 | 目标外观变化 | 状态化工具是否可用 |
| 调整光照方向 | 亮暗与阴影变化 | 效果参数是否具有连续响应 |

最后两项是本项目提出的测试条件，不是已经逐帧验证的 Solaris 演示功能。强控制应该体现为：用户能明确切换语义，同一语义下行为有规律，不必靠多次试错猜测当前模式。

### 4. 后续帧：对象变化会牵动整幅画面

搬动灯在视觉上可能同时需要处理原位置的背景、目标位置的遮挡、局部反射与阴影。用户感觉到的是“对象在场景里发生变化”，所以效果自然程度与目标跟随精度需要分别打分。

漂亮的阴影不证明存在光线追踪或物理求解器；合乎常识的遮挡不证明存在完整三维场景；布料看起来连续也不证明材质参数可准确编辑。要确认这些更强能力，需要量化几何、可重复的光照测试、明确的数据结构或导出接口。

## 公开技术与尚缺的实现细节

公开方法的价值在于提供研究方向：顺着已发生动作生成后续状态，缩短生成过程，并减少连续生成中的误差累积。它不能代替部署规格。

| 问题 | 当前结论 | 若要复现，应补充什么 |
| --- | --- | --- |
| 每一次 mousemove 是否调用 LLM？ | 未公开调用频率；不能作此断言 | 事件日志、LLM调用时间戳、任务提示更新条件 |
| 输入是向量还是画面轨迹？ | 未公开编码 | 坐标空间、按钮状态、时间间隔、轨迹聚合方式 |
| 是否需要明确选中对象？ | 交互结果可表现为选中，但内部表示未知 | 目标保持机制、歧义处理、失焦/取消规则 |
| 是否能一直保持状态？ | 本项目未实测 | 长会话、返回原状态、重复编辑、遮挡恢复测试 |
| 是否实时？ | 官方使用“实时/交互速度”；本项目没有测量 | 输入到显示的 p50/p95 延迟、丢帧率、硬件和网络条件 |
| 不经 DOM 是否等于没有代码？ | 不等于 | 事件采集、流式显示、会话、服务与业务接口仍需实现 |

复现探索中可以尝试归一化坐标、按键状态、时间戳、轨迹缓冲和显式操作模式，但这些都是**我们的实现建议**。不能把它们写成 Solaris 已采用的方案。

“DOM 去除”也须谨慎：官方讨论的是视觉生成省去传统的设计到界面实现转换，不能据此确认产品外围没有 DOM 或任何传统代码。即使画面由模型生成，提交订单、保存内容、调用数据库或提供无障碍语义仍然需要可验证的系统连接。

## 怎样区分可观赏与可控制

本项目建议把测试结果拆成五个维度，避免一个“效果很好”掩盖交互问题：

1. **目标精度**：鼠标落点与受影响对象是否一致；邻近对象是否误改。
2. **过程精度**：拖动途中是否跟随；停顿、反向和释放是否被识别。
3. **语义精度**：预先声明的移动/变形/视角/材质意图是否正确执行。
4. **状态精度**：对象身份和操作模式是否保持；重复执行与逆操作是否稳定。
5. **视觉质量**：背景补全、遮挡、材质和光影是否自然。此项独立于物理正确性。

对于灯的移动，可人工标注其可见中心，以“对象中心位移”与“鼠标位移”的偏差度量空间响应。若存在透视、旋转或形变，需要预先指定锚点，不能直接要求所有像素等距移动。对光照和材质效果，不适用对象位移指标，应测效果范围、响应单调性和不相关区域变化。

端到端延迟应从**真实输入发生**量到**第一帧可见响应**，并另报“稳定完成”的时间。生成 FPS 不能替代这个指标：网络、事件缓冲、语义更新与显示缓冲都可能增加等待。

## 原创验证矩阵

以下全部是待执行实验。每组应固定起始图、任务提示、画面分辨率与录制条件；若服务允许固定随机性，应记录相关参数，若不允许则明确写出。建议每个条件重复 10 次，保留失败，不只挑成功片段。

| ID | 操作与对照 | 记录什么 | 可以排查的问题 |
| --- | --- | --- | --- |
| M01 空白点击 | 同一语义下分别点对象、邻近背景、远处背景；设无输入基线 | 受影响区域、误变次数、自然动画幅度 | 是否所有点击都触发泛化效果 |
| M02 对象边界 | 从目标中心逐步向边界外点击/拖动；重叠对象增加对照 | 目标正确率、边界内外选择变化 | 精细选取能力与歧义 |
| M03 逆向路径 | 向右拖后沿原路径返回，最终回到起点 | 位置残差、尺寸/外观变化、背景残留 | 可逆性和状态漂移 |
| M04 相同终点 | 直线、绕圈和折线路径抵达同一终点 | 中间响应、终点结果、无关区域变化 | 使用过程还是主要使用终点 |
| M05 快慢拖动 | 同一路径用 0.5、2、5 秒完成 | 响应延迟分布、漏动、过冲、丢帧 | 输入采样与速度敏感性 |
| M06 中途停顿 | 拖动中停 2 秒再继续，另设直接拖完 | 暂停后是否仍运动、恢复是否连续 | 是否真正受持续输入控制 |
| M07 遮挡往返 | 把目标拖到前景物体之后，再拖回可见处 | 身份、纹理、尺度恢复、遮挡顺序 | 隐藏区域的状态保持 |
| M08 放手 | 同一拖动分别正常释放、画面外释放；另设无拖动释放 | 放手后继续变化时长、失控率 | 动作终止与画面外输入处理 |
| M09 重复操作 | 重置后重复同一动作 10 次，再在同一会话中重复 | 成功率、终点方差、累积变化 | 可重复性与随机性 |
| M10 语义切换 | 同起始图同路径，明确指定移动、缩放、视角等模式 | 语义正确率、旧模式残留、切换耗时 | 相同鼠标动作的可编排能力 |
| M11 长时漂移 | 连续 5–10 分钟操作，每隔 30 秒返回基准位置 | 身份/文字/布局偏移、误改区域、失败时间 | 长会话的累积误差 |
| M12 效果局部性 | 小目标换色/纹理，旁边放相似但无关对象 | 目标变化、邻物泄漏、边缘与阴影变化 | 材质操作的作用范围 |
| M13 光影对照 | 若可指定光照，往返调整同一参数；使用无输入基线 | 阴影连续性、亮度响应、返回一致性 | 视觉规律稳定性；不直接证明物理准确 |
| M14 无操作基线 | 相同提示下保持鼠标静止，对照等长操作会话 | 自发运动与漂移幅度 | 将环境动画与鼠标因果作用分开 |

统计时同时报告中位数、较差分位数和失败率。对象中心、遮挡关系等需人工复核；自动图像相似度可能把合理的光影变化当成错误，也可能忽略物体身份变更。未经校准的模型评分不能单独作为真值。

## 面向家装场景的实际意义

如果上述控制成立，这种能力可用于快速探索“这盏灯放到另一边”“画作变大一点”“沙发换另一种外观”等视觉方案。它适合帮助用户比较感受，减少把视觉想法翻译成工具操作的步骤。

要进入精确设计阶段，还需要尺寸、碰撞、资产身份和可保存的编辑状态。商业交付还要能回答“用的是什么产品”“尺寸是否容得下”“结果能否重建”。仅凭一个连续生成的演示，无法认定这些能力已经存在，更无法量化对家装职业的替代程度。
