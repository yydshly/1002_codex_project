# 真人上装效果样板计划

日期：2026-10-06。状态：0.15.0研究样板实施与复核。两组研究实拍、45项已安装包、离线权重/解析缓存与4项小GPU内核核查已有记录。四组真实任务已完成20步、输出576×768，首次内存不足失败无图保留；原衣重建与实拍不一致，三组跨衣缺实穿对照。189项产品与18项Python后端测试通过，真实分界/放大/平移/复位、选款撤销及PNG预览/评审JSON内容已核查；下载写盘、剪贴板一致性和异常专项另验，不视为普遍可用或效果全通过。

## 用户任务与本轮结果

用户选择一张真实人物照片和一件真实上装的商品图，得到这件衣服在该人物照片中的生成外观参考，观察颜色、版型外观、领口、袖口和可见细节，再决定是否继续看这件商品。样板先解决“能否看懂、是否有参考价值”，不把鼠标动作或成功返回一张图作为效果合格的充分条件。

首轮限定单人、正面或接近正面的上装照片与登记商品。人物必须来自实拍，衣物必须有真实照片与可核查来源；不以生成真人、原创三维展样、手工贴图或修图替代真实输入。优先选择有同一人物穿着同一目标衣物的实拍对照的样本；没有该对照仍可展示生成结果，但必须明确“暂无同人同衣实拍对照，不能据此判断还原准确度”。

现有三维试衣间继续承担固定人体的搭配、观察和方案保存；真人样板增加照片中的外观参考。两者输出不同，不能把三维拖放验收等同于真人照片试穿已成功。

## 自部署的含义与上线条件

采用 FASHN 预训练方案，由本机后端接收登记输入并执行推理。这里的“自主实现”是自己接入、部署、控制流程和保存结果，不是从零训练模型。不得写成纯浏览器运算或不需要模型；也不将自部署等同于不受模型、权重或数据许可约束。

GPU、驱动、运行依赖、权重与加载情况以实际环境记录为准；健康检查可提交或模型成功加载，不等于已完成真实推理和效果验收。代码许可、权重许可和每组输入图片的许可分别登记；能下载或仓库开源不足以证明全部内容可用于公开或商业展示。具体模型版本、提交、权重文件校验、参数、设备、分辨率、耗时、显存与失败信息应留在实现和验收记录中，不在主操作页面堆放工程术语。

当前安装与核查情况见 [本机运行说明](tryon-runtime.md)。首次真实任务 `0702f8ebda354a11b07958e6db4ef579` 的[失败元数据](tryon-runs/initial-failed-0702f8eb.json)和[stderr](tryon-runs/initial-failed-0702f8eb.stderr.log)保留原始事实：跨衣输入已送本机，采样尚无完成步，最终OOM失败且没有生成图。调整预处理网络驻留后，四组真实任务完成，分别63.34、49.58、41.84、52.58秒；有限成功不证明所有内存问题或硬件都适用。此失败须继续计入运行记录，不用实拍参考或预置图填充输出。

验收运行须确认请求由登记的本机服务处理，并保留可追踪的输入、任务记录和实际输出；不能把外部服务返回结果、缓存图或预置图称为本次本机生成。固定已生成样板可以作为结果回看，但应标“已生成示例”，与“本次生成”分开。GPU未就绪或推理失败时如实显示原因，不能自动换成伪造成功图。

首轮效果验收以经核查的公开登记样本为基线。当前网页已加入自己的照片与商品图的本机选择入口；该路径仍属实验输入，不是已验收的任意人像服务，文件能解码也不意味着人物、衣类或拍摄方向满足效果范围。用户照片没有公开样本的来源与实拍对照，必须分别标记。

本机服务会把任务输入、元数据与实际结果写入本机任务目录，不等于仅存于浏览器内存或自动删除。照片存放位置、保留与删除方式、后端日志和第三方请求范围需在实际上传验收时说明与核对；不能把“仅送本机服务”解释成不留任何照片文件。

## 输入、生成图与实拍对照的展示

工作区始终可看到“人物实拍”“真实上装图”“生成试穿参考”三种不同来源。若有可核查的同人同衣照片，再增加“同人同衣实拍对照”；没有时显示缺失说明，不能用另一位模特、另一件近似衣物或另一张生成图填补。

生成结果在页面、放大查看和导出的图片中都应保留可见的“生成试穿参考”标记。标记不能只存在文件元数据、说明弹窗或下载前页面。实拍对照不带生成标记，但必须有单独来源标签。真人照片的真实与输出图的生成性质同时讲清楚。

每组样本记录：样本ID、人物图与衣物图的原始来源、授权范围、原文件校验、是否经过裁剪、目标上装类别、是否有同人同衣实拍、实拍拍摄条件的可比性。人物输入应与目标上装形成真实换装任务；若输入已穿目标衣物，只能作保留或一致性检查，不能冒充换装效果。不同姿态、镜头和光线下的实拍可以提供局部参考，不能直接当作逐像素还原标准。

目前已登记两组 VITON-HD 原衣成对研究照片，来源与非商业许可见 [样本来源](tryon-sources.md) 及 [运行清单](../web/tryon/samples/manifest.json)。研究编号不是可售SKU，原相机文件和额外肖像/品牌商用授权也没有核验。同编号衣物图与已经穿该衣物的人像，不构成“人物穿另一件衣物的输入 + 目标衣物图 + 同人换穿目标衣物实拍”的完整换装对照。样板应分别登记配对一致性样本与跨衣换装样本；后者没有独立实拍对照时，直接标明缺失，不能借用前者宣称换装准确。研究非商业许可样本与真实商业可用素材分别判断，不把这两组登记照片写成可商用商品素材。

不虚构品牌、商品链接、价格、库存或真人穿着评价。没有可核查商品编号时可使用样本编号，并称“登记衣物样本”，不能称已接入真实商品购买。

## 操作与预期

| 用户操作 | 应看到的结果 | 验收方式 |
| --- | --- | --- |
| 选择登记人物和上装，查看来源 | 实拍输入、衣物类别和对照有无清楚可见 | 核对展示文件与源记录，确认不是合成输入或错误配对 |
| 点击生成 | 明确的等待状态，完成后显示本次任务结果；失败明确说明 | 本机任务记录与输出文件对应；不以预置图冒充本次结果 |
| 换另一件登记上装再生成 | 新结果属于当前人物与新上装，旧结果仍可区分 | 核对样本ID与任务ID，避免延迟结果覆盖新选择 |
| 对比输入、生成结果与可用实拍 | 领袖、图案、面部、手臂和衣服遮挡可放大观察 | 按以下质量表记录问题；无实拍时保留不能核查项 |
| 保存结果与回看 | 图片保留生成标记，关联输入样本与生成记录 | 实际打开保存文件核查，不仅验证按钮可点击 |

取消、重试、重复点击、切换样本与服务中断的具体行为，须在实际实现后验证。不要在本计划中提前声称取消会终止GPU任务或所有异常均能恢复。网页应保留输入并明确当前任务状态，避免用户误把旧输出认作新选择的结果。

输入准备开始时就锁定本次人物、衣物和照片形式；连续上传只采用当前有效选择，不按较旧任务的完成顺序覆盖新选择。任务状态、元数据和已解码图片必须属于同一任务与输入组合才显示，旧图片不能在新结果读取时暂作新结果。网络读取中断与推理失败分别处理：读取中断仍保留可恢复的任务关联，重新检查应能明确恢复读取或放弃任务，不能让用户误以为只能重复生成。无效本机存档应整体忽略，不改变画面背后的输入。

## 效果验收：必须展示能看见的问题

首先登记评审样本，再执行推理，不能只保留成功图片。至少安排基础换装和有图案、开襟或手臂遮挡的较难正面样本；如素材暂不足，应明确哪些维度未覆盖。每个输入组合、实际运行和失败结果都留档，失败不得从成功率的分母中删除。

| 维度 | 核查内容 | 结果记录与边界 |
| --- | --- | --- |
| 面部与头部 | 与输入并排看五官、肤色、发型、耳部是否出现明显重画或漂移 | 记录可见变化；有限照片的肉眼通过不等于身份保持保证 |
| 身体外观 | 身高比例、肩宽、躯干轮廓、手臂与手指是否被异常改变 | 明显变形列为不合格；照片外观不能作为身体尺寸测量 |
| 衣物身份与细节 | 颜色、领型、袖长、开襟、图案位置、口袋和可见材质是否与输入衣物一致 | 特别记录图案或文字被编造、衣款被替换、结构被删改，不能只评价整体好看 |
| 遮挡与边缘 | 手臂/手/头发与衣服前后关系、领口、腋下和下摆是否合理 | 遮挡反转、融合、露出不该出现的旧衣、重复肢体或衣服悬浮均单列 |
| 实拍依据 | 是否真为同人同衣，姿态、视角与光线是否可比 | 无实拍只评可见合理性和输入一致性，不能写“与真实穿着一致”；有实拍也不证明其他人物/衣款适用 |
| 结果可追溯 | 来源、输入组合、生成标记、任务与输出是否一致 | 任一错误绑定或生成图未标记均阻止作为合格样板交付 |

每项记录“可接受 / 明显问题 / 无法核查”，附局部图或文字依据；严重脸部或身体变形、明显错误衣款、遮挡错误和来源混淆不能被平均总分掩盖。样板首页展示代表性合格结果，同时提供错误样本与限制入口。若仅完成一组真人样板，应称“一组实测样板”，不称普遍可用。

实拍依据有无由来源记录确定，独立于人工效果评分。没有同人同目标衣跨衣实拍的组合，该项固定为缺依据，不能手工改成通过；原衣配对只能评分原衣重建参照，并持续说明不验证另换新衣。导出的评审也应保留这一事实。

自动相似度若后续采用，仅作辅助并注明适用条件；没有可信可比实拍时，不生成虚构的还原率、准确率或保真分。用户评价也应询问能否辨认目标衣物和理解结果限制，不只问图片是否漂亮。

## 产品价值与验收指标

首轮可信用途是商品浏览中的正面上装外观参考，以及样品沟通中的效果对照。是否能帮助实际选款，需要让使用者完成“选择衣物 → 查看结果 → 指出关键外观 → 保存或继续查看”的任务，而不只是观看演示。

待实际记录的指标包括：生成完成与失败次数、端到端等待时间、用户无需指导完成任务的比例、误把生成图当实拍的人数、能否正确辨认衣物关键细节、保存与回看的来源一致性，以及难例出现明显错误的次数。质量结果按有无实拍对照分开汇报，样本总量与失败量同时报告。GPU安装成功、接口返回成功和网页按钮可用只是实现前提，不替代效果与用户任务验收。

## 可扩展产品方向（后续规划，尚未接入）

网页入口为 [AI 换装效果预览的产品方向](../web/tryon.html#product-directions)。当前照片输入、本机模型生成、对照观察和人工评审保留；本场景暂缓继续研发，项目回到其他能力推进。以下为可选产品路线，不增加已交付场景或能力计数，也不提前验收 C19。

| 方向 | 用户价值 | 待补充能力与证据 |
| --- | --- | --- |
| 真实商品选款导购（优先） | 为导购、客服和顾客比较真实衣款，形成商品候选清单 | 真实 SKU、颜色款、价格、库存、商品链接；C19 购物联动仍待接入 |
| 造型师提案工具 | 对同一客户比较衣款、说明选择理由并保存提案 | 客户档案、方案管理、批量生成与批注；多件套装另行研发 |
| 品牌视觉预演 | 在实拍前筛选模特、衣款与构图方案 | 授权素材、批量处理和商品细节审核；预演不代替商品实拍证据 |
| 个人数字衣橱 | 管理已有衣物与待购商品，辅助日常搭配 | 衣物归档、多件搭配、下装、鞋履及个人数据保存管理 |
| 尺码与合身推荐（独立模块） | 根据人体和商品真实数据辅助选码 | 人体测量、每款实测尺寸和实际试穿反馈；布料模拟另需纸样与面料参数，生成图本身不能提供合身结论 |

建议下一轮限定一个品牌、10–20 款有授权的真实上装 SKU。用户选择三款衣服，生成后并排比较、放大检查领口和图案、圈出问题、排序收藏，保存带真实商品信息的候选清单。鼠标操作服务于选款、核对和沟通；试点范围、商品目录与上述工作流尚未实施。

推进前需要采集“人物原照片＋目标商品图＋同人实际穿着图”的三方对照，记录衣款、图案、身体及遮挡偏差；衡量无指导完成率、衣款辨认、候选缩小情况、等待时间、失败与误把生成图当实拍的情况。商业使用须取得人物和商品素材授权，并替换有非商业限制的研究素材与组件。图片生成成功不代表用户选款价值或购物联动已经通过。

公开路线参考：[Google 个人照片换装与购物商品目录](https://blog.google/products-and-platforms/products/shopping/studio-quality-digital-try-on/)，[FASHN 图像试穿与尺码预测的区别](https://fashn.ai/virtual-try-on)。仅用于了解产品路线和边界，方案继续采用我们的部署与流程，不以调用这些产品的后台服务为前提。

## 首轮明确不承诺

不判断尺码、松紧、舒适、面料手感、承托或真实垂坠；不从人物照片推断身体测量。不验证背面、侧面、转身、动态视频、多人、下装、鞋履或任意遮挡姿态，不把正面生成图当作真实三维穿着。输出可能改变人物或服装细节，使用者应以真实商品资料及实穿为依据。

真人样板不自动接通C19购物关系，更不意味着已有真实库存、价格、订单或支付流程。公开样本的有限成功也不等于可直接接受任意消费者照片或上线商用。

PNG导出预览已实际核查为576×812（原图576×768加44px生成注记）；评审JSON全文已核对并留档，含真实输入组合、任务ID、元数据和缺实拍依据。提供复制/保存入口；内置浏览器自动下载落盘及剪贴板字节一致性未验证。
