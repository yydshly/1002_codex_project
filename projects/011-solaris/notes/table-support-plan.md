# 新桌网格与台灯支撑：下一阶段实施与验收说明

日期：2026-10-07。状态：调查与设计，尚未实施。

本轮仅只读调查客厅代码并记录方案，没有实现通用支撑模块，没有增加新模型资产，没有接入新的桌面识别或附件关系。下列接口、状态字段与测试均为下一阶段建议，不代表现有功能。**本方案不得计入当前 35/36 能力映射，不得据此提高完成率或宣称已验证新模型泛化。** 当前轮优先完成用户可用的备份可靠性闭环；几何实现应在另行确定范围后开始。

## 1. 要验证的能力与第一阶段边界

目标是把同一套几何规则应用到此前未逐件适配的静态桌模型，自动识别可放置的水平面，并检查完整台灯底座能否贴面、是否越过凹边或孔洞，以及灯体是否与桌沿、桌上障碍相交。桌子和灯的变换、鼠标事务、保存与恢复必须保持这项关系。

第一阶段只覆盖静态、水平支撑面与可识别的单一平面灯底。暂不承诺任意斜面、曲面、多脚支撑稳定性、材质承重、重心稳定性或真实刚体接触。几何支持条件不能表述为真实物理稳定性。柜架、斜面等扩展要在本阶段通过后单独定义规则和验收。

## 3. 坐标、单位与原网格前置提取

需要明确区分三层坐标：GLB 源网格及节点坐标、归一化后的资产坐标、项目实例的世界坐标。统一以 Y 向上、X/Z 为水平面；项目空间使用明确的设计尺寸约定。

- 三角面提取必须应用完整节点世界矩阵，包括嵌套平移、旋转、缩放及矩阵节点；同时处理 indexed / non-indexed 几何。负行列式的源节点变换必须正确处理绕序，不能只变换位置后沿用错误法线。无法可靠处理的情况应明确拒绝。
- 法线由变换后的几何位置计算，不以材质或平滑着色法线判断平面。透明玻璃有实际三角片就不能被当作孔洞；缺少三角片的孔洞也不能被材质外观填平。
- 先分析原模型，后加入本项目的书杯、点光源、选择框等辅助对象。检测输入与后续障碍输入应分别保留来源，禁止分析最终展示组的最高点来决定台面。
- 归一化应是单一、可记录的统一变换。可选择保留已确认的源物理尺寸，或对所有新桌统一采用一个预先冻结的设计高度规则；两者不能混用。现有茶几的 0.43 m 是本项目指定的设计高度，不能据此声称新素材本来就具有这个实测高度。
- 资产单位、上方向、归一化策略、归一化矩阵与源文件指纹必须能审计和复现。不得凭包围盒大小猜测厘米/米，也不得为让某个模型通过而临时改缩放、偏移或阈值。
- 首阶段限制为静态三角网格；骨骼、形变、动画、非有限坐标、不可逆变换、退化或超出资源上限的资料返回明确错误。GLB 是否包含外部引用、压缩扩展及对应解码能力，也应在资产注册时验证，不能默默只分析成功加载的部分。

资产元数据可以登记来源、许可、单位和文件指纹；不得登记手写台面、支撑高度、摆放点或专属检测参数。后者会把未知模型验证变为逐件适配。

## 4. 共用平面识别与完整底座覆盖

建议纯几何模块输出可序列化、不可变的分析资料，不依赖 Three.js 渲染器、DOM 或鼠标事件。

1. 按统一法线、平面误差、顶点焊接和连通规则收集近水平候选面。所有阈值以同一单位和同一规则版本表示；在留出验证前冻结。
2. 将候选三角片映射到平面二维坐标，保存它们的实际并集、外边界、孔洞与分离分量。不能以桌子包围矩形或整个台面的凸包替代有效区域。
3. 使用确定的排序和标识生成候选面资料。多个同样合理的候选返回 `ambiguous`，等待明确选择；不能永远选模型最高处。人工选择自动检测出的面是操作，不等于在代码中写死该模型的支撑面。
4. 从灯原网格提取最低接触平面及完整底座轮廓。第一阶段仅接受能可靠识别的单一平面底座；点接触、曲面底、多脚或无法消除歧义的接触资料明确拒绝。保存模型根坐标到接触坐标的固定变换：现有模型按整体包围盒居中，灯底中心不一定在模型根的 X/Z 零点，不能把根坐标直接当成底座锚点。底座轮廓与整灯外包围盒分别保存，灯臂越出底座不应被误认为底座悬空，但灯体碰撞仍需验证。
5. 在同一平面坐标中验证完整底座。设台面有效区域为 `S`，经当前灯姿态变换的底座为 `P`，统一安全边距为 `δ`，需要证明 `P` 加边距后的区域完全包含于 `S`。必须检查整个覆盖区域，不能只验中心、四角或少量射线；特别要拒绝完全被底座包住、却没有与底座外边界相交的台面孔洞。
6. 平面贴合还需验证接触轮廓各点的高度误差符合全局公差。完整灯体对桌沿、原模型台面上方结构及书杯等障碍分别做几何碰撞检查；底座包含关系不能代替灯体碰撞检查。障碍判定要覆盖实体包含，不能只找三角片交线而漏掉灯体完全进入一个障碍体的情况。对无法可靠解释为实体的障碍，可使用明确的保守包络或拒绝，不能静默忽略。

覆盖判定可采用带孔多边形差集等方法，但需要明确数值稳健性：量化误差、边界公差和安全边距应形成保守误差界；不确定时拒绝。不能以“剩余面积小于一个经验值”忽略细孔、窄缝或悬空边。若使用几何库，需另行核对其算法适用范围、许可及本地运行条件。

建议接口仅作为实施草案：

```text
extractStaticMesh(asset, normalization) -> meshData | rejected
analyzeSurface(meshData, frozenPolicy) -> surfaces | ambiguous | rejected
analyzeContactBase(lampMeshData, frozenPolicy) -> baseProfile | rejected
checkPlacement(surface, baseProfile, transforms, anchor, obstacles)
  -> { valid, reason, worldPose, evidence }
```

`reason` 至少区分无合格面、歧义、孔洞、悬空/越边、接触高度不符、灯体碰撞、不支持的几何和数值不确定。`evidence` 保存实际采用的面、变换及规则版本，不能只返回一个无法核查的布尔值。这些函数当前尚不存在。

## 5. 变换、鼠标事务与持久化

附件关系应保存父对象 ID、父资产指纹、规则/分析版本、支撑面 ID、局部锚点和相对朝向。支撑面高度来自分析资料，不能再次使用整体资产高度。候选 ID 的生成应依赖稳定的几何资料与规则版本，不能依赖异步加载顺序。

- 灯继续作为独立实例渲染。父桌的变换决定锚点与相对朝向；灯自身的尺寸保持明确，尤其不能直接继承父桌非均匀缩放而改变灯体形状。
- 第一阶段实例变换限定为平移、绕 Y 旋转和正尺度/轴向拉伸。每次变换都在统一空间重验支撑、接触与碰撞。任意倾斜、剪切等不在范围内的变换明确拒绝。
- 桌子缩小、拉伸、旋转或换型时，桌与灯作为一个事务验证。失败不应自动缩灯、换面、夹位或挪灯；应给出理由并保留事务基线。若未来增加自动寻找站位，必须是对所有模型使用同一算法的明确操作，结果仍需完整验证。
- 对“始终贴面滑动”，除了每个采样姿态合法，还需检查两次鼠标事件之间的扫掠区域。平移不能跨过孔洞或分离台面，旋转需要保守的连续覆盖判定；不能只把事件终点都合法当成中间也合法。
- 如果允许拿起后跨孔搬运，应另行定义该手势及预览，不将它表述为始终贴面滑移。第一阶段可以先只接入贴面滑动。
- 非法释放、Escape、失焦、指针取消与捕获丢失恢复整次桌灯事务；一次撤销/重做恢复桌、灯与附件字段。保存、备份和导航如何处理未完成事务应统一明确，建议先取消再保存稳定状态。
- 恢复必须通过与编辑相同的关系验证。资产缺失、指纹变化、分析版本不支持、面 ID 无效、非法锚点或变换都应拒绝并给出原因，不能回退为矩形约束后声称成功恢复。

几何资料可以由固定资产在启动前预生成并按指纹验证，或在加载完成后生成；在资料就绪前，涉及附件的编辑、恢复和自动保存必须有明确的等待/拒绝状态。不能先按旧矩形约束改写备份，再等模型加载。首阶段可采用随项目注册的本地 GLB，避免同时引入任意用户上传与资产打包问题。

## 6. 至少三个独立留出模型的协议

现有 `modern_coffee_table_01` 和 `modern_coffee_table_02` 是已适配素材，只能用于回归，不能计入新模型泛化数量。程序生成的简单几何夹具也不能代替真实新模型。

1. 先定义第一阶段可接受资产范围、全局阈值、归一化规则与通过/拒绝条件；记录规则版本和指纹，再开始留出验证。
2. 准备至少三个此前未逐件适配、相互独立的新静态桌模型，保留来源、许可、原文件指纹与单位/变换资料。不同导出版本、同模型换材质或同一模型变形不算三个独立样本。
3. 覆盖不同台面形状和节点组织，尽可能包含圆边、凹边/孔洞、嵌套变换等差异。若这些差异未包含在真实留出样本中，另用几何夹具补充，但报告中必须分别列出。
4. 使用同一程序、同一阈值与同一归一化策略运行全部样本。禁止按模型名称分支、手写台面高度/面列表/摆放点、临时调参或隐藏失败模型。
5. 冻结后的样本必须记录候选面、完整底座有效放置、靠边/跨孔等非法放置、桌灯变换，以及自动拒绝的原因。允许拒绝范围外资产，但必须公开归类；不能把全部拒绝算成已经具备可用的新模型支撑能力。
6. 要宣称达成“至少三个新桌模型可用”，必须有三个范围内独立模型在同一冻结规则下完成实际桌灯任务。拒绝样本另行统计，不抵消这三个正样本。若修改规则，应提升版本，并用新的未调参样本再次验证；原留出样本转为回归集，不能继续冒充未见样本。

视觉人工核查只确认检测和摆放是否符合源网格，不用于给某个模型补专属参数。所有失败、歧义和范围限制都应保留在报告中。

## 7. 测试范围与阶段门槛

| 阶段 | 建议产物 | 进入下一阶段的门槛 |
| --- | --- | --- |
| A：冻结范围与资料格式 | 单位/坐标约定、全局规则、资源上限、源资产与分析资料格式 | 明确现有尺寸校准与新网格分析的区别；无逐模型支撑字段；能解释每项拒绝条件 |
| B：纯几何模块 | 静态提取适配器、候选面分析、底座提取、完整覆盖与碰撞判定 | 通过凹边、完全包住的孔洞、窄缝、分离面、嵌套变换、绕序、非有限值及数值不确定等有意义测试；仅中心/角点通过不算验收 |
| C：留出模型验证 | 至少三个独立新模型的逐项证据与另外的拒绝样本 | 冻结规则下三个正样本完成任务；无专属面、摆放点或阈值；失败与拒绝公开记录 |
| D：状态与事务接入 | 有版本的附件字段、几何资料解析、联合编辑与恢复验证 | 移动/旋转/缩放/拉伸/换桌、扫掠、非法释放、取消、失焦、一次撤销/重做、保存恢复和资产不匹配都保持桌灯关系；现有场景回归通过 |
| E：真实产品任务验收 | 阅读角任务、操作说明、截图/状态与验收记录 | 用户用同一流程操作三个新桌，保存并重开得到一致的合法桌灯关系；说明能区分已验证能力、拒绝边界和未接入能力 |

测试须区分纯数学夹具、真实资产几何验证、状态/事务测试与浏览器实际操作，分别记录证据。新用例数量不是泛化证据；截图也不能代替完整底座和持久化验证。

当前仅完成本文所依据的代码调查和方案设计。A–E 的实施产物与验收均未完成；没有新资产，也没有相关新增测试通过结果。待备份可靠性闭环完成并确定下一阶段实施范围后，才开始上述工作。
