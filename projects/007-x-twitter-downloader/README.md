## 能力与原理

用户粘贴公开 X/Twitter 帖子的链接，网站解析媒体信息，展示可用版本，用户选择后由浏览器打开视频地址并保存。网站说明无需注册或提供 X 登录信息，链接会交给本站服务器和外部解析服务处理。[功能说明](https://x-twitter-downloader.com/zh-CN)、[处理方式](https://x-twitter-downloader.com/zh-CN/privacy-policy)

```text
帖子 / 网页链接
      ↓
获取页面、播放器接口或媒体元数据
      ↓
找到真实视频地址或播放清单
      ↓
展示标题、封面与可用版本
      ↓
选择版本 → 请求媒体数据 → 保存文件
```

“识别”是把来源页面与其媒体资源对应起来，不必进行画面内容识别，也不一定直接解析 HTML。公开前端将链接通过 `POST /api/parse-video` 发送到后台；接口返回视频信息和 `direct_download_url`，下载按钮打开这个地址。具体后台接口、解析供应商和实现库未确认。

本次测试返回的视频地址指向 `video.twimg.com`，已有版本从 480×270 到 3840×2160；高分辨率来自源视频已有资源，不是下载器生成或提升画质。响应摘录见 [解析示例](notes/parse-example.json)。

## 研究价值判断

解析媒体信息、选择版本、请求文件及合并分段都是已有的技术路径。仅复现“粘贴链接后下载”的流程，技术创新与基础研究价值有限；当前没有必要深入追踪该站未公开的后台实现。

工程难度仍可能来自网站适配、登录状态、链接有效期、分段下载和长期维护。这些问题在后期明确目标平台与产品需求后再研究，当前将网站作为产品参考归档。

## 对后期视频下载产品的指导

| 参考点 | 后期产品设计 |
| --- | --- |
| 链接驱动 | 输入来源页面链接，一次触发解析 |
| 可确认的结果 | 展示标题、封面、时长、实际分辨率和格式，帮助确认目标视频 |
| 版本选择 | 提供清晰度选择，说明文件大小、音视频是否需要合并 |
| 下载任务 | 展示进度与结果；按实际需求增加取消、重试和断点续传 |
| 失败反馈 | 区分无视频、权限不足、链接过期、解析不支持和网络失败 |
| 来源关联 | 保存来源网页、视频信息、解析日期、选择的版本和本地文件路径 |

前 3 项参考本站输入、解析与选项流程；任务管理、细分错误及来源关联是面向后期产品的设计建议，不表示本站已经实现全部功能。第一版应先支持少数目标网站或直接视频文件；可评估 yt-dlp 作为解析与下载引擎，再补充所需适配。[yt-dlp 官方文档](https://github.com/yt-dlp/yt-dlp#embedding-yt-dlp)

## 能力边界

- 在自己的浏览器中能播放，不代表下载程序具备相同访问权限或能成功解析。
- MP4 等完整文件通常可直接保存；HLS / DASH 需要处理播放清单和分段，必要时合并音视频。
- `blob:` 是浏览器生成的引用，需要继续确认它背后的媒体文件或分段请求。[MDN blob URL 说明](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob)
- 网站之间的媒体加载方式和访问条件不同，不承诺任意网页都能下载。

后续出现明确开发需求时，以具体网站与测试样本验证可行性；本次归档作为产品起点参考。
